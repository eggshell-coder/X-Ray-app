# Contributing

## Development workflow

1. Create a focused branch from `main`.
2. Make the smallest change that addresses the issue.
3. Run the frontend build and the relevant backend checks locally.
4. Do not commit patient-identifying images, secrets, virtual environments, or
   generated temporary reports.
5. Open a pull request describing the change and how it was tested.

## Pull requests

Pull requests should include:

- a clear summary of the change;
- deployment or configuration changes, if any;
- test steps and expected results;
- screenshots for visible UI changes.

The model is for research and education only. Contributions must not present
the output as a clinical diagnosis.
